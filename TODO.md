So either we preprocess English -> Katakana so the Japanese voice works?  Or even better, extend the Kokoro service to do this heavy lifting.  Consider using CMU Pronouncing Dictionary (CMUdict)
- Add more AI providers
- Let the txt2img call override the model and sampling parameters instead of inheriting whatever the SD server has loaded.  Today neither call site in app.js sends `override_settings` or `sd_model_checkpoint`, so a portrait renders with whatever checkpoint is loaded at that moment — and the hardcoded `cfg_scale: 1` / `distilled_cfg_scale: 6` quietly assume a distilled model.  `distilled_cfg_scale` is guarded (Forge applies it only if `sd_model.use_distilled_cfg_scale`), but `cfg_scale` is not, so a non-Flux checkpoint silently produces washed-out, prompt-ignoring images with no error — against a Forge default of 7.0.  The Settings lamp now names the loaded checkpoint, which makes this diagnosable but not preventable.  `override_settings` is confirmed present in Forge Neo's live OpenAPI schema, along with `override_settings_restore_afterwards` so the server isn't left switched.  Two things to settle first: checkpoint filenames differ per machine (flux-2-klein-4b here, flux1-dev-bnb-nf4-v2 on the LAN box), so it has to be configurable rather than hardcoded — probably a Settings field seeded from the `/sdapi/v1/sd-models` list; and switching the checkpoint on a shared server would surprise anyone else using it, so it may want to be opt-in.  Worth considering whether the sampling parameters should move with it, since they and the model have to agree.
