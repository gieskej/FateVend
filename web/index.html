How to Use Vend of Fate

After rolling and generating a scenario, there are three ways to get it into AI Dungeon.

Copy & Paste (Side-by-Side)

Open Vend of Fate and AI Dungeon in separate windows side by side. Use the Copy button next to each field (Title, Description, Opening, Plot Essentials, Author's Note, and each character entry) to copy just that field, then paste it into the matching field while creating your scenario in AI Dungeon.

Or use ⚙ Copy Full Text To Clipboard (JSON) at the bottom to copy everything at once as structured JSON, if you'd rather edit the output in your favorite editor.

Download Package (.zip)

Click ↓ Download Package (.zip) to save the whole scenario as a timestamped archive: scenario.json, the protagonist's portrait.png, and an npc-portraits/ folder holding one image per NPC you generated. Import it into AI Dungeon whenever you're ready, or keep it as a backup of a scenario you liked.

Only portraits that were actually generated are included — the archive is never blocked on missing images.

Auto Import (Beta)

One-click import via a local Playwright-driven script — no copy/paste required. Only available when you run the app yourself (serve.sh, or Start-FateVend.cmd on Windows), since it depends on Node.js, Playwright, and a local Chromium install.

On the hosted demo the button stays hidden, and the import server refuses requests from it. Browsers do let an HTTPS page reach localhost, so this is enforced deliberately rather than being a technical impossibility: the importer can act on your AI Dungeon account, so only pages you run yourself are trusted with it. Use Copy & Paste or Download Package on the demo — both work everywhere.

Need to allow another origin — a copy of the app you host yourself, say? Start the server with it listed explicitly: AIDUNGEON_ALLOWED_ORIGINS="https://example.com" node tools/aidungeon-server.mjs. Only add origins you control.

  1. Add AIDUNGEON_EMAIL and AIDUNGEON_PASSWORD to your .env file at the project root — these are your AI Dungeon login credentials.
  2. Run npm install and npx playwright install chromium once, if you haven't already.
  3. Start (or restart) serve.sh — or Start-FateVend.cmd on Windows. Either launches the import server on port 7432 alongside the web app automatically.
  4. After generating a scenario, an ↑ Import to AI Dungeon (Beta) button appears below the Download button. Click it — a browser window opens and fills in the title, description, plot, story cards, and portrait automatically.

The button only appears once the local import server is detected running — if you don't see it, double-check the server is running and Playwright is installed.

Setup

Vend of Fate requires at least a text provider to function. You may choose from various cloud-hosted models, or from a self-hosted Ollama instance.

Text Providers
Anthropic — Claude

Claude writes the character entries, scenario description, opening, and NPC entries. Select it in the Text Provider selector after entering a key.

  1. Go to console.anthropic.com and sign in or create an account.
  2. In the left sidebar, click API Keys.
  3. Click Create Key, give it a name, and copy the key immediately — it won't be shown again.
  4. Paste it into the Anthropic API Key field above. Keys start with sk-ant-.

New accounts include free credits. Paid usage is billed per token — a typical generation costs a few cents.

Google Gemini

Gemini writes the same content as Claude. Select it in the Text Provider selector after entering a key. It has a free tier, which makes it the easiest place to start.

  1. Go to aistudio.google.com/api-keys and sign in with your Google account.
  2. Click Create API key and choose or create a project.
  3. Copy the key and paste it into the Gemini API Key field above. Keys start with AIza.

Free-tier limits are per Google Cloud project, not per key — extra keys in the same project share one quota. Limits are capped per minute and per day and change over time; check AI Studio for current numbers. Paid tiers lift them.

Ollama (Local LLM)

Run text generation entirely on your own machine — no API key or internet required. Ollama serves open-weight models (Llama, Mistral, Gemma, etc.) via a local REST API.

  1. Install Ollama and run it. The default URL is http://localhost:11434.
  2. Pull a model: ollama pull llama3.2. Larger models give richer output; 7B+ recommended.
  3. If running on another machine, use its hostname or IP: http://192.168.1.50:11434. Ensure OLLAMA_ORIGINS=* is set so the browser can reach it.
  4. Enter the URL in Ollama URL and the model name in Ollama Model above.

Quality varies by model size. Llama 3.2 (3B) works but a 7B–14B model will produce noticeably better results.

Image Providers

Image providers render character and NPC portraits. It is optional — you may choose a cloud service or a self-hosted one.

Local Stable Diffusion

A local Stable Diffusion instance is used for portrait generation and takes priority over the Stability AI cloud service. Generates portraits on your own hardware with no per-image cost.

  1. Install Stable Diffusion WebUI Forge — recommended for its native Flux1-dev support.
  2. Launch with the --api flag enabled: add --api to your launch arguments or webui-user.bat.
  3. The default URL is http://localhost:7860. If running on another machine, use its IP address, e.g. http://192.168.1.50:7860.
  4. Paste the URL into the Stable Diffusion URL field above. The app calls the /sdapi/v1/txt2img endpoint (AUTOMATIC1111-compatible format, which Forge implements).

Install a Flux1-dev or SDXL model for best results. The portrait prompts are optimized for Flux1-dev with danbooru-style tags.

Stability AI

Used for portrait generation when no local SD instance is reachable. Requires a paid Stability AI account.

  1. Go to platform.stability.ai and sign in or create an account.
  2. Click your profile in the top right, then API Keys.
  3. Click Create API Key, copy it, and paste into the Stability AI Key field above. Keys start with sk-.

Image generation costs credits. New accounts receive a small free allocation.

Image Options

Once an image backend is configured, the protagonist card shows a Generate Portrait button, and each NPC card shows a portrait menu with its own Generate Portrait option.

Auto-generate NPC portraits (Settings → Options tab) automatically generates a portrait for every NPC right after scenario generation finishes — one at a time — instead of requiring you to open each NPC's portrait menu manually. Requires an image backend to be configured; off by default.

TTS Providers

Text-to-speech providers add an optional feature — reading the generated scenario aloud, to help you get into the story and decide if it's worth playing in AI Dungeon.

Browser Narration (Free)

Uses your browser's built-in speech synthesis to read the character entries aloud. No key or server required — works offline.

  1. Select Browser (built-in) in the Narration Provider selector.
  2. Pick a voice in the Voice dropdown — available voices depend on your OS and browser.

Quality and voice selection vary a lot by platform (Chrome, Edge, and Safari all ship different voice sets).

Kokoro LAN (Local)

Run a local Kokoro TTS server for higher-quality narration on your own hardware, no per-request cost.

  1. Run a Kokoro server that exposes the OpenAI-compatible /v1/audio/speech endpoint (e.g. Kokoro-FastAPI). Default port is 8880.
  2. If running on another machine, use its IP address, e.g. http://192.168.1.50:8880.
  3. Paste the URL into the Kokoro URL field above, then select Kokoro LAN in the Narration Provider selector.
  4. The Voice dropdown auto-populates from the server's /v1/audio/voices endpoint if reachable, otherwise falls back to a built-in voice list.
OpenAI TTS (Cloud)

Cloud-based narration using OpenAI's text-to-speech API. Requires a paid OpenAI account with API access.

  1. Go to platform.openai.com/api-keys and sign in or create an account.
  2. Click Create new secret key, copy it, and paste into the OpenAI TTS Key field above. Keys start with sk-.
  3. Select OpenAI in the Narration Provider selector, then choose a voice in the Voice dropdown.

Billed per character of text sent. This is a separate key/account from the Anthropic key used for text generation.

Narration Options

Once a Narration Provider is selected (Settings → Narration tab), each generated scenario shows narrate buttons next to the description, opening, plot, protagonist, and each NPC entry, plus a Narrate All button that reads the whole scenario in sequence and auto-scrolls to whichever section is currently being read.

Voice and Speed (Narration tab) override the genre's default voice/pace for whichever provider is selected. Pick — Genre default — (Kokoro/OpenAI) or System default (Browser) in the Voice dropdown to clear the override and go back to the genre's built-in voice.

Auto-play Narrate All (Settings → Options tab) automatically starts reading the full scenario aloud as soon as generation finishes, once the intro music fades out — no need to click Narrate All manually.

Genre Packs

A genre pack adds a whole new playable genre — its own species or clans, professions, tensions, secrets, names, art and music — without changing any code. Packs are pure data, so importing one can't run any program on your machine.

Installing a pack
  1. Open Settings → Genre and choose a .json or .zip file under Genre Packs.
  2. The new genre appears in the carousel straight away — no reload, no restart.
  3. Installed packs are stored in your browser and come back automatically next visit. Each has a Remove button.

A malformed pack is rejected with a list of exactly what's wrong, and nothing half-installs. Two ready-made examples ship in web/genre-packs/.

Making your own

No coding required — a pack is one text file. The full guide is CREATING-A-GENRE.md in the project repository: a minimal working pack you can copy, every field explained, and the mistakes that pass validation and then behave oddly.

One thing worth knowing before you import someone else's pack: a pack supplies the writing instructions its genre sends to the AI. That text is yours to read — treat an untrusted pack the way you'd treat any untrusted document.

Privacy
Your API keys

Keys you enter in Settings are stored only in your own browser and are sent only to the provider you select. This app has no server of its own, so there is nowhere else for them to go — and nobody else using the same page can see them.

On a shared or public computer, clear the key fields when you're done: the next person using that browser profile would otherwise find them filled in.

Anonymous usage stats

The app reports one anonymous event per completed scenario: which genre, and which text / image / narration providers were used. Nothing else — no keys, no characters, no scenario text, no accounts, no cookies, and no way to link two events to the same person. Uploaded genre packs report only the word pack, never the pack's own name.

Turn it off any time under Settings → Options → Privacy. The choice is remembered in your browser.

Local .env Setup (Optional)

If you run the app yourself, you can pre-fill your cloud API keys from a .env file at the project root instead of typing them into Settings every time. Purely a convenience — entering keys directly in Settings always works too, and is the only option on the hosted demo.

Only do this on a computer only you use. A .env file stores keys in plain text, and every browser profile on that machine gets them pre-filled.

.env File

serve.sh (or serve.ps1 on Windows, which Start-FateVend.cmd runs for you) reads .env at the project root and writes the keys into generator/config.js on startup, so the browser can use them without the .env file itself ever being served. config.js is gitignored and never published.

  1. Create a .env file at the project root (next to the web/ folder).
  2. Add one KEY=value line per key you want pre-filled: ANTHROPIC_API_KEY, GEMINI_API_KEY, STABILITY_API_KEY, SD_URL, OLLAMA_URL, OLLAMA_MODEL, TTS_KOKORO_URL, TTS_OPENAI_KEY.
  3. Restart the server — it regenerates generator/config.js from .env every time it starts.

AIDUNGEON_EMAIL and AIDUNGEON_PASSWORD (used by Auto Import, above) work differently — they're read directly by the Node-side importer script and are never baked into generator/config.js or exposed to the browser.

NSFW_IMAGE_PROMPT_SUFFIX replaces the text appended to the appearance prompt when Settings → Options → NSFW is checked and the character is an adult (18+) — e.g. ", sexy unibrow, <lora:MyFluxLoRA>". Falls back to a plain ", sexy" when unset. Leading punctuation matters: it's appended directly after the rest of the prompt with no separator added, so keep the leading ", " unless you want it glued onto the previous word.
